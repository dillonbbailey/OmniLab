## Explicit compatibility boundaries

- **Native MoonRay RDL/DSO execution:** retain legacy data for migration; use USD/MaterialX/MDL outputs for the new renderer. An RDL exporter can remain a separate optional legacy tool, but RTX does not consume MoonRay RDL as its native scene format.
- **Shader families and LPE expressions:** preserve editor affordances and report conversion coverage. Implementing the same UI does not establish equivalent shading semantics.
- **Mesh/UDIM baking:** Lunatic's `UV_BAKING_PLAN.md` describes future work. Its absence in an initial OmniLab release is not a regression from the inspected application.
- **Asset publishing:** retain its existing current-composed-state semantics; do not claim it preserves all unselected variants or original instance sharing.
- **EXR display:** Lunatic uses an 8-bit bounded preview while retaining original floating-point file values. A full OCIO/HDR display is a useful future enhancement, not an existing parity requirement. Deep EXR visualization is also outside the current baseline.

## Release checklist

For each row, record implementation owner, source fixture, shared-core test, Qt real-input evidence, GPU evidence where applicable, status and any accepted limitation. The Qt release can be called a reproduction when all first-release rows have demonstrated outcomes or an explicitly agreed replacement. The ovUI version must rerun the same document/command tests and its own input tests; passing the Qt suite alone does not certify its UI.
